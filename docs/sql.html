Documentation / SQL reference

SQL reference

What the engine accepts, with an example for each part, followed by the places where NusaDB deliberately behaves differently and why.

Data types

Every type below is native: it compares, sorts, and brings its own operators and functions rather than being stored as text under another name.

GroupTypes

JSON

sql
CREATE TABLE docs (id INT PRIMARY KEY, body JSONB);
INSERT INTO docs VALUES (1, '{"user":{"name":"ana","tags":["a","b"]},"active":true}');

SELECT body -> 'user' ->> 'name'          AS name,
       body #>> '{user,tags,0}'        AS first_tag,
       body @> '{"active":true}'          AS is_active,
       jsonb_path_query(body, '$.user.tags[*]') AS tag
FROM   docs;

Ranges, network and bit strings

sql
SELECT int4range(1, 10)                   AS r,          -- [1,10)
       int4range(1,10) @> 5            AS contains,
       int4range(1,10) && int4range(5,20) AS overlaps,
       host('192.168.1.5/24'::INET)      AS just_host,
       '192.168.1.0/24'::CIDR >> '192.168.1.5'::INET AS in_subnet,
       B'1011' & B'1101'                     AS bit_and;

Vectors

Four distance operators: <-> L2, <=> cosine, <#> negative inner product, <+> L1. An index answers only the metric its operator class declared, so build one index per metric you query.

sql
CREATE TABLE items (id INT PRIMARY KEY, emb VECTOR(3));
INSERT INTO items VALUES (1, '[1,0,0]'), (2, '[0,1,0]');

CREATE INDEX items_emb ON items USING hnsw (emb vector_cosine_ops);
SET hnsw_ef_search = 100;   -- higher trades latency for recall

SELECT id, emb <=> '[1,0,0]' AS distance
FROM   items ORDER BY distance LIMIT 5;

Defining objects

Tables with constraints, generated columns and defaults; indexes including partial, expression and descending; views, materialized views, sequences, domains, schemas, databases, enumerated and composite types, triggers and routines.

sql
CREATE TABLE orders (
  id       BIGSERIAL PRIMARY KEY,
  customer BIGINT REFERENCES customers (id) ON DELETE CASCADE,
  total    NUMERIC(12,2) CHECK (total >= 0),
  tax      NUMERIC(12,2) GENERATED ALWAYS AS (total * 0.11) STORED,
  placed   TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX orders_big ON orders (customer) WHERE total > 1000;   -- partial
CREATE INDEX orders_low ON customers ((lower(email)));         -- expression
CREATE TABLE archive (LIKE orders);                             -- copy the shape, not the rows
Temporary tables and cursors are available

A temporary table belongs to the session that made it, is invisible to others, and disappears when the session ends. ON COMMIT DELETE ROWS and ON COMMIT DROP are accepted. Cursors work over a connection with DECLARE, FETCH and CLOSE. A view over one table with no aggregate is auto-updatable, so INSERT, UPDATE and DELETE through it reach the base table.

ALTER TABLE … RENAME COLUMN is refused when something records the column by name

A user-defined check, foreign key, index, default, view, trigger or policy keeps the column name as text. Rather than rename and leave those pointing at a name that no longer exists, the engine refuses and names what is in the way. Drop it, rename, recreate it.

Querying

Joins of every kind, lateral joins, scalar and quantified subqueries, set operations, DISTINCT ON, grouping sets, window functions with named windows and ROWS/RANGE/GROUPS frames including EXCLUDE, recursive common table expressions, TABLESAMPLE and WITH ORDINALITY.

sql
SELECT c.country,
       count(*)                                 AS orders,
       sum(o.total)                             AS revenue,
       rank() OVER (ORDER BY sum(o.total) DESC) AS by_revenue
FROM   customers c
JOIN   orders    o ON o.customer = c.id
WHERE  o.placed >= now() - INTERVAL '30 days'
GROUP BY c.country
HAVING count(*) > 2
ORDER BY revenue DESC;

  country | orders | revenue | by_revenue
 ---------+--------+---------+------------
  SG      |      1 |  900.00 |          1
  ID      |      3 |  245.50 |          2

Changing data

sql
INSERT INTO customers (email, country) VALUES ('ana@example.com', 'ID')
ON CONFLICT (email) DO UPDATE SET country = EXCLUDED.country
RETURNING id, joined;

MERGE INTO stock t USING shipment s ON t.sku = s.sku
WHEN MATCHED             THEN UPDATE SET qty = t.qty + s.qty
WHEN NOT MATCHED         THEN INSERT (sku, qty) VALUES (s.sku, s.qty)
WHEN NOT MATCHED BY SOURCE THEN UPDATE SET qty = 0;

TRUNCATE orders CASCADE;      -- also empties tables that reference it

Access control

Roles, membership, object and column-level grants, and row-level security policies, all enforced inside the engine.

sql
CREATE ROLE analyst LOGIN PASSWORD 'secret';
GRANT readers TO analyst;

GRANT SELECT ON customers TO readers;
GRANT SELECT (email, country) ON customers TO analyst;   -- column-level
ALTER TABLE orders ENABLE ROW LEVEL SECURITY;
CREATE POLICY own_rows ON orders
  USING (customer = current_setting('app.customer')::BIGINT);

Where NusaDB chooses differently

These are decisions, not gaps, and each one has a reason.

Text sorts by byte value

Comparison and ordering are bytewise, equivalent to a C collation; COLLATE "C" and "POSIX" are accepted and locale collations are refused. Byte order is deterministic and does not change when a system library is upgraded, which is what keeps an index valid across upgrades. The visible effect is that uppercase sorts before lowercase.

Coercion is explicit

The engine does not insert implicit conversions between unrelated types. Cast with ::TYPE when mixing them, and you always know which conversion happened.

NUMERIC division has a fixed scale

Division produces a fixed scale rather than deriving one from the operands. The value is the same; only how many digits are kept differs. Round explicitly when a scale matters.

JSON is stored parsed

JSON and JSONB both store a parsed value, so key order and insignificant whitespace are not preserved. Keep the original text in a TEXT column when byte fidelity matters, such as a signed payload.

Materialized views are snapshots

A materialized view holds the result of its last REFRESH. Incremental maintenance is opt-in with WITH (incremental = true), and asking for it on a body that cannot be maintained incrementally is an error rather than a silent downgrade.

A query over its memory budget fails rather than spilling

With work_mem set, a stage that materialises more than the budget fails with an error naming the limit, the bytes involved and how to raise it, and the server stays responsive. That keeps one large query from slowing every other query, at the cost of not finishing it.

Session settings

sql
SET search_path = reporting, public;
SET work_mem = 67108864;
SET statement_timeout = '30s';
SET max_autocommit_retries = 50;      -- 0 turns the retry off
SET myapp.tenant = '7';             -- application variables need a class prefix
SHOW search_path;
RESET ALL;

An unrecognised parameter name is an error rather than a silent no-op, and a read-only parameter reports that it cannot be changed.

Not accepted in this release

Recognised and refused with a clear message rather than half-implemented: advisory locks, PREPARE/EXECUTE as statements over a connection (use the extended query protocol), SET TIME ZONE, index methods other than B-tree and HNSW, and locale collations.
